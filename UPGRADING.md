# Upgrading

**Extracting a release archive over a working tree adds and overwrites files.
It never deletes them.**

Every file removed upstream survives in your checkout, keeps being picked up by
the test glob and the module graph, and fails with an error about its *contents*
rather than about the fact that it should no longer exist. Two files have hit
this already:

| Leftover | Removed in | Symptom |
|---|---|---|
| `tests/e2e_flask.js` | 2.1.0 — replaced by `tests/e2e.test.js` | `__dirname is not defined`, and it imported `static/js/api.js`, split up in 2.0.0 |
| `tests/bridge.test.js` | never shipped by this project | `require is not defined in ES module scope` |

`tests/shell.test.js` now names any file in `tests/` that this release does not
ship, so the message says *delete this* rather than *fix this*.

## Upgrading

```bash
unzip -o sandeshika-v2.1.0.zip     # adds and overwrites
npm run prune                      # lists anything left over — changes nothing
npm run prune:apply                # removes it (git rm when tracked)
npm install && npm test
git status                         # review the deletions before committing
```

`MANIFEST.txt` ships with the release and lists every file in it. That is what
lets `prune` tell a leftover from something you added — an archive on its own
has no way to say *and delete that*.

Only these directories are reconciled:

    static/  tests/  tools/  app/src/  .github/workflows/

The repository root is deliberately **not** managed, because that is where
`settings.json`, keystores and `local.properties` live. `prune` is a dry run by
default; a tool that deletes on an accidental invocation is worse than the
problem it solves.

If a file it flags is genuinely yours, either keep it outside those directories
or run `npm run manifest` to fold it in.

## Files that are yours, not the release's

Keep these; the archive does not contain them:

- `settings.json` — your Medha token. Gitignored, mode 0600.
- `local.properties` — Android SDK path, generated by Android Studio.
- Any keystore.

## After any upgrade

```bash
npm run check                 # lint + types + 13 JS suites
python3 tests/server_test.py  # server, proxy, Android resources
```

`shell.test.js` is the one that catches upgrade damage specifically: stale
files, unresolvable imports, a service-worker cache list that has drifted, and
the five version constants disagreeing.

## The five version constants

`package.json`, `static/js/main.js`, `static/sw.js`, `app.py` and
`app/build.gradle.kts` all carry the version. When they disagree, the running
app tells the user their cache is stale — a warning that is then wrong for
everyone and quickly learned to be ignored. Never edit them by hand:

```bash
python3 tools/bump_version.py 2.2.0
```
